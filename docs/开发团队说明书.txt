五、训练参数说明
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

--d-model     模型核心维度（越大容量越大，384 ≈ 11M 参数，256 ≈ 5M 参数；4GB GPU 建议 ≤384）
--num-layers  Transformer 编码器层数（推荐 4 层；2 层欠拟合、6 层过拟合且 VRAM 不够）
--batch-size  批大小（GPU 4GB 建议 32；CPU 建议 16）
--lr          学习率（AdamW 推荐 1e-4）
--epochs      最大训练轮数（30 轮配合 early stopping，实际约 15-25 轮收敛）
--grad-accum  梯度累积步数（模拟更大 batch，GPU 用 2，CPU 用 4）
--device      运行设备（cuda / cpu）
--contrastive-weight  对比学习损失权重（0.2 适中；过高会压制主任务）

训练自动执行 early stopping（验证损失连续 15 轮不下降则停止）。
最优模型自动保存到 --output 指定路径，指标保存到同名 .json 文件。

六、模型架构说明
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TCMNet（定义在 tcm_recommender/model.py）是一个多任务推荐模型：

症状编码器 SymptomEncoder
  → Embedding + 可学习位置编码 + 6/4 层 Pre-LN Transformer + AttentivePooling
  → 输出 [batch_size, d_model] 的症状表征向量

药材编码器 HerbEncoder（双塔）
  → 文本塔：CharCNN（药材功效+主治文字的字符多热矩阵 → 全连接）
  → 属性塔：分类/性/味 3 路 Embedding → 拼接 → 投影
  → Sigmoid 门控融合文本特征和属性特征
  → 输出 [num_herbs, d_model] 的药材嵌入矩阵

交叉注意力排序器 CrossAttentionRanker
  → 症状表征(Q) × 药材/方剂嵌入(K,V) 做交叉注意力
  → 逐项打分 → 输出 [batch_size, num_items] 的原始评分

多任务输出头
  → 证型分类头 SyndromeHead：3 层 MLP → softmax 输出
  → 药材推荐头：CrossAttentionRanker → sigmoid 多标签
  → 方剂推荐头：CrossAttentionRanker → softmax 分类

对比学习 ContrastiveLoss
  → 症状表征和药材嵌入分别投影到 256 维
  → InfoNCE 损失：拉近匹配的(症状,药材)对、推远不匹配对

8.1 数据库质量
药材表 herbs 已完成清洗：删除 34 条非药名错误条目（功效动词类），
合并 449 组同名药材（保留最完整记录并合并字段），
删除 14 条归经误当药名的条目。
当前 3010 条药材均为唯一名，无重复。如后续重新导入数据需再次清洗，
可执行以下 SQL 清理（注意合并禁忌/功效信息）：
  DELETE FROM herbs WHERE id NOT IN (SELECT MIN(id) FROM herbs GROUP BY name)

8.2 关联矩阵
症状-药材关联矩阵：5283 非零关联 / 200×3010 = 602000 总数，密度 0.88%
每症状关联药材数：平均 26.4，中位数 6.0，最大值 482（"咳嗽"、"发热"等常见症状）
关联基于功效/主治文本子串匹配，精确度有限。如需改进可用 LLM 或专家标注。
