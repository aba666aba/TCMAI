1. 系统概述
================================================================================

1.1 设计目标

本系统旨在构建一个智能化、专业化的中医药桌面应用，通过深度学习模型
结合传统中医药知识库，为用户提供准确、可靠的中医药知识查询和推荐服务。

设计目标包括：
（1）提供自然语言症状输入和智能辨证分析
（2）基于深度学习模型实现药材和方剂的精准推荐
（3）内置配伍禁忌检测和毒性药材警示
（4）支持离线运行，不依赖网络连接
（5）支持 PyInstaller 打包为独立桌面应用

1.2 设计原则

（1）模块化设计：各功能模块职责清晰，低耦合高内聚
（2）单一数据源：所有配置和知识数据统一管理
（3）安全性优先：用户数据脱敏处理，合规提示
（4）弹性降级：AI 模式不可用时自动切换到规则引擎
（5）线程安全：多线程环境下数据访问加锁保护

1.3 整体架构

系统采用三层架构设计：

  ┌─────────────────────────────────────────────────────────────┐

文件位置：src/core/tcm_config.py
功能说明：所有业务模块共享的单一数据源

数据结构：
  SYMPTOM_LIST（列表，33项） - 基础症状列表
  SYMPTOM_ALIAS_MAP（字典，44项） - 口语到标准术语的映射
  SYMPTOM_INFO（字典，33项） - 症状的类别、描述、相关证型
  SYMPTOM_KEYWORDS（字典，15组） - 症状关键词到标准名的映射
  SYNDROME_DEFINITIONS（字典，9个） - 证型定义（症状、治法、方剂）
  SYNDROME_RULES（字典，3个） - 症状到证型的规则匹配
  FALLBACK_HERBS（列表，15味） - 内置降级药材知识
  FALLBACK_FORMULAS（列表，14首） - 内置降级方剂知识
  FALLBACK_SYMPTOMS（字典，15种） - 内置降级症状信息
  INCOMPATIBLE_HERBS（字典） - 十八反、十九畏、孕妇禁用
  TOXIC_HERBS（列表，7种） - 毒性药材
  UI_QUICK_SYMPTOMS（列表，15种） - 前端快捷标签

2.3 症状处理管线模块（src/core/symptom_pipeline.py）

文件位置：src/core/symptom_pipeline.py
功能说明：统一的症状处理入口，合并检测、分析功能

类：SymptomPipeline
  detect(query) - 从自然语言查询中检测症状
    - 基于 SYMPTOM_KEYWORDS 关键词匹配
    - 返回匹配到的症状名称列表

  analyze(symptoms) - 分析症状列表
    - 委托 SymptomAnalyzer 进行标准化和证型推断
    - 返回标准化症状、证型、禁忌、建议

  process(query, symptoms) - 完整处理管线
    - 步骤1：关键词检测症状
    - 步骤2：合并外部传入症状
    - 步骤3：执行症状分析（标准化+证型推断+禁忌检查+建议生成）
    - 步骤4：获取每个症状的详细信息
    - 返回完整的分析结果字典

2.11 深度学习模型模块（tcm_recommender/model.py）

文件位置：tcm_recommender/model.py
功能说明：TCMNet 深度学习模型定义

类层次结构：
  PreLayerNormTransformerEncoderLayer
    - 预层归一化 Transformer 编码器层
    - 多头自注意力 + 前馈网络 + GELU 激活
    - 层序：LayerNorm -> Attention -> Residual -> LayerNorm -> FFN -> Residual

  LearnedPositionalEncoding
    - 可学习的位置编码（最大长度 64）

  AttentivePooling
    - 注意力池化层
    - 输入 [B, L, D] -> 注意力权重 -> 加权求和 -> 输出 [B, D]

  SymptomEncoder
    - 症状编码器：Embedding + 位置编码 + N层 Transformer + 注意力池化

  HerbEncoder
    - 双塔结构药材编码器
    - 文本塔：字符多热编码 -> MLP -> D 维
    - 属性塔：类别/性味/归经嵌入 -> MLP -> D 维
    - 门控融合机制

  CrossAttentionRanker
    - 症状-物品交叉注意力排序器
    - 症状向量作为 Query，物品嵌入作为 Key/Value

  SyndromeHead
    - 证型分类头（3 层 MLP -> 18 类）

  TCMNet（主模型）
    - SymptomEncoder：症状编码
    - HerbEncoder：药材编码
    - CrossAttentionRanker（药材）：症状-药材评分
    - CrossAttentionRanker（方剂）：症状-方剂评分
    - SyndromeHead：证型分类
    - 多任务联合训练

  create_model() - 模型工厂函数

2.14 数据生成管线模块（tcm_recommender/data_pipeline.py）

    五阶段生成策略：
    阶段1 - 证型驱动（约50%）：为每个证型生成症状子集变体
    阶段2 - 药材驱动（约20%）：为每味药材匹配关联症状

    阶段4 - 组合增强（约25%）：随机症状组合 + 关联矩阵标签

  save_to_npz(filepath) - 保存为 NumPy 压缩格式

3. 数据库设计
================================================================================

3.1 数据库概览

数据库文件：data/tcm_knowledge.db
数据库引擎：SQLite 3
数据总量：约 5000 条记录

包含 4 个核心表：
  药材表（herbs） - 3497 条
  方剂表（formulas） - 1019 条
  中成药表（patent_medicines） - 约 60 条
  民间验方表（folk_remedies） - 约 220 条

3.2 药材表（herbs）

字段说明：
  id          INTEGER PRIMARY KEY  - 主键自增
  name        TEXT                  - 药材名称
  category    TEXT                  - 药材类别（补气药、清热药等）
  nature      TEXT                  - 药性（温、寒、平、凉）
  flavor      TEXT                  - 药味（甘、苦、辛、酸、咸）
  meridian    TEXT                  - 归经（脾、肺、心、肝、肾经）
  efficacy    TEXT                  - 功效描述
  indications TEXT                  - 主治病症
  usage       TEXT                  - 用法用量
  contraindications TEXT            - 禁忌
  source      TEXT                  - 来源典籍

3.3 方剂表（formulas）

字段说明：
  id          INTEGER PRIMARY KEY  - 主键自增
  name        TEXT                  - 方剂名称
  category    TEXT                  - 方剂类别
  source_book TEXT                  - 出处典籍
  composition TEXT                  - 组成药材
  dosage      TEXT                  - 剂量
  functions   TEXT                  - 功能主治
  indications TEXT                  - 适应症
  usage       TEXT                  - 用法
  modification TEXT                 - 加减变化
  explanation TEXT                  - 方解

3.4 中成药表（patent_medicines）

字段说明：
  id              INTEGER PRIMARY KEY  - 主键自增
  name            TEXT                  - 中成药名称
  category        TEXT                  - 类别
  composition     TEXT                  - 组成
  functions       TEXT                  - 功能主治
  indications     TEXT                  - 适应症
  usage_dosage    TEXT                  - 用法用量
  contraindications TEXT                - 禁忌

3.5 民间验方表（folk_remedies）

字段说明：
  id          INTEGER PRIMARY KEY  - 主键自增
  disease     TEXT                  - 主治疾病
  remedy      TEXT                  - 验方名称
  ingredients TEXT                  - 组成成分
  method      TEXT                  - 使用方法
  source      TEXT                  - 来源

5. 数据流设计
================================================================================

5.1 查询处理数据流

  用户输入 -> 输入校验 -> 症状检测 -> 模式选择 -> 结果生成 -> 界面更新

  （1）用户输入：文字输入 + 快捷标签选择
  （2）输入校验：1-1000字符，症状不超过20项
  （3）症状检测：SymptomPipeline.detect() 关键词匹配
  （4）模式选择：默认 AI 模式，不可用时降级快速模式
  （5）结果生成：
      - AI 模式：模型推理 -> 格式化回答 -> 安全校验
      - 快速模式：规则引擎 -> 知识库搜索 -> 生成回答
  （6）界面更新：显示回答、免责声明、保存历史

5.2 AI 模式数据流

  症状文本 -> 症状解析 -> 模型推理 -> 结果后处理 -> 回答格式化

  （1）症状文本：用户输入的症状描述
  （2）症状解析：TCMRecommender.parse_symptoms()
      - 文本 -> 症状 ID 序列（基于 200 症状词库）
  （3）模型推理：TCMNet.forward()
      - SymptomEncoder -> 症状向量
      - SyndromeHead -> 证型分类（18类）
      - CrossAttentionRanker -> 药材/方剂评分
      - Contrastive loss 计算
  （4）结果后处理：安全校验（十八反、十九畏、孕妇禁用、毒性检测）
  （5）回答格式化：_format_recommendation_as_answer()
      - 生成【症状分析】【推荐方剂】【推荐药材】【安全提示】【养生建议】

5.3 快速模式数据流

  症状文本 -> 关键词检测 -> 证型匹配 -> 知识库搜索 -> 回答生成

  （1）症状检测：detect_symptoms() 基于 SYMPTOM_KEYWORDS
  （2）证型匹配：SymptomAnalyzer 规则匹配（置信度评分）
  （3）知识库搜索：KnowledgeBase.search() / search_herbs() / search_formulas()
  （4）回答生成：generate_fallback_answer()
      - 生成【症状分析】【推荐方剂】【相关知识】【养生建议】

6.1 数据安全

7. 深度学习模型设计
================================================================================

7.1 TCMNet 模型架构

模型总参数量：11,192,726

输入层：
  symptom_ids - 症状 ID 序列（最长 32，1-based）
  herb_features - 药材特征（字符多热编码 + 属性索引）

编码器：
  SymptomEncoder（4层 Transformer）：
    Token Embedding（200 症状）
    LearnedPositionalEncoding（最大 64）
    4x PreLayerNormTransformerEncoderLayer
      - d_model=384, nhead=8, dim_feedforward=2048
      - 激活函数：GELU
    AttentivePooling -> [B, 384]

  HerbEncoder（双塔结构）：
    文本塔：字符多热矩阵（2172维）-> MLP -> 384维
    属性塔：类别(61) + 性味 + 归经 -> Embedding -> MLP -> 384维
    门控融合：门控权重 * 文本特征 + (1-门控) * 属性特征 -> 384维

排序器：
  CrossAttentionRanker：
    症状向量 (Query) x 药材嵌入 (Key/Value) -> 注意力权重 -> 评分

分类头：
  SyndromeHead：3 层 MLP -> 18 类证型

损失函数（多任务）：
  证型分类：CrossEntropyLoss
  方剂排序：CrossEntropyLoss（正样本 vs 负样本）
  药材推荐：加权 BCE Loss（正负样本不平衡处理 ~10:1）
  对比学习：Supervised InfoNCE（temperature=0.07）

7.2 多任务学习

模型同时优化四个任务：
（1）证型分类 - 确定患者的中医证型
（2）方剂推荐 - 推荐最匹配的经典方剂
（3）药材推荐 - 推荐对症的单味药材
（4）对比学习 - 学习症状与药材的语义关联

训练策略：
  优化器：AdamW（lr=1e-4, weight_decay=1e-5）
  学习率调度：CosineAnnealingWarmRestarts
  梯度裁剪：max_norm=2.0
  早停：patience=15
  混合精度：CUDA 自动启用
  Label Smoothing：0.05

7.3 训练数据生成

数据生成器：TCMDataPipeline
数据规模：约 100,000 样本
症状数量：200 种
证型数量：17 种
药材数量：3,497 种
方剂数量：1,019 种

五阶段生成策略：

  阶段1 - 证型驱动（约50%，50,000样本）
    为每个证型生成症状子集变体
    15% 概率注入其他证型的症状作为噪声
    增强模型的证型辨别能力

  阶段2 - 药材驱动（约20%，20,000样本）
    遍历每味药材，查找其关联症状
    基于 efficacy + indications 文本匹配
    建立症状-药材关联矩阵

  阶段3 - 方剂驱动（约12.5%，12,500样本）
    为每个方剂解析其药材组成
    通过药材关联症状反向推导
    建立症状-方剂关联矩阵

  阶段4 - 组合增强（约25%，25,000样本）
    随机组合 2-6 个症状
    通过关联矩阵自动生成标签
    增加数据的多样性和覆盖度

  阶段5 - 负采样（约10%，10,000样本）
    生成语义不匹配的症状-药材对
    标签赋值为 -1.0
    用于对比学习训练

数据输出格式：
  压缩 NPZ 文件
  包含字段：
    symptom_ids - 症状 ID（1-based，padded to 32）
    symptom_mask - 填充掩码
    herb_labels - 药材多标签
    formula_labels - 方剂标签
    syndrome_labels - 证型标签
    sample_weights - 样本权重
