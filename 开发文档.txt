# TCMAI 中医药智能方剂生成系统 — 开发手册

## 项目概况

**核心目标**：构建中医药智能方剂生成系统，基于 **自然语言理解 → 知识图谱推理 → 方剂生成（含用量）→ 禁忌筛查** 的完整管线，辅助医生提高诊断效率。

项目路径：`E:\Tom\TCMAI` | Python >=3.10 | GPU: RTX 3050 4GB (CUDA 12.4)

## 系统能力

1. **自然语言理解** — 精准理解用户自然语言病情描述，提取症状/证型
2. **知识图谱驱动推荐** — 症状→证型→药材/方剂推理（KG + TCMNet 模型双通道融合）
3. **药材 + 用量推荐** — 从 `herbs.usage` 字段提取结构化用量范围，附于推荐药材
4. **传统方剂匹配** — 匹配到的传统方剂一并输出
5. **十八反十九畏筛选** — 自动过滤配伍禁忌，减少医生工作量（6层安全筛查）
6. **知识图谱可视化** — 展示病症相关的知识子图

> 设计原则：生成的药方**不需要确保真实可用**，医生做最终判断。系统做好基础安全筛选即可。

## 数据流架构

```
用户输入 → TCMDesktopService.query()
           ├─ AI模式(主) → TCMRecommender.recommend → KG融合推荐 → 安全筛查 → 输出(含dosage+方剂+图谱)
           │                ├─ TCMNet 模型预测(症状→药材/方剂/证型)
           │                ├─ KG 推理(symptom_to_recommendation + recommend_by_symptoms)
           │                └─ 加权融合(model_weight * 模型分 + kg_weight * KG分 + boost)
           └─ 输出（方剂 + 药材 + 禁忌筛查 + 知识图谱）
```

完整训练和推理管线：
```
DB → data_pipeline(500K样本)→ TCMNet训练 → 模型推理 → KG融合 →安全检查 → 输出
     ↑                               ↑
extended_config(228症状/30证型)    kg_cache.pkl(知识图谱)
```

AI模式走深度学习（tcm_recommender/recommend.py）+ KG融合（src/kg/recommender.py）。
桌面服务层在 src/desktop/service.py 中协调调用流程。

## TCMNet 模型架构 (model.py)

SymptomEncoder(Embedding+位置编码+4层Transformer+AttentivePooling) → [B,d_model]
HerbEncoder(CharCNN文本塔+属性Embedding塔, Sigmoid门控融合) → [H,d_model]
CrossAttentionRanker(症状Q × 药材/方剂K,V) → 逐项评分
多头输出：证型分类(softmax) + 药材推荐(sigmoid) + 方剂推荐(softmax)
对比学习：InfoNCE拉近匹配(症状,药材)对

## 训练数据管线 (data_pipeline.py)

5阶段生成 500K+ 样本（30证型/228症状/2961药材/717方剂）：
1. 证型驱动(50%)：按30证型定义生成症状变体+推荐药材标签
2. 药材驱动(20%)：每味药材匹配关联症状
3. 方剂驱动(12%)：每个方剂匹配症状+药材组成标签
4. 组合增强(25%)：随机症状组合+关联矩阵top-20标签
5. 负样本(17%)：零关联症状-药材对（label=-1.0，训练时作为明确负标签参与loss）

关联矩阵构建（7层递增）：
1. 文本子串匹配（功效/主治含症状名）
2. 方剂组成反推（方剂有症状→组成药材继承）
3. 药材分类语义匹配（如"解表"→恶寒/发热/头痛）
4. 功能关键词匹配（零关联药材/方剂补漏）
5. 药材别名继承（别名继承正名的关联）
6. 症状同义词映射（同义词症状继承关联）
7. 硬编码兜底（仍有零关联的药材/症状做最后补救）

### 药材用量数据

- `herbs.usage`：1934/2961（65.3%）非空，格式为自由文本（如"煎服，3-10g"、"先煎，15-60g"）
- `formulas.dosage`：仅 1.7% 非空且内容为方剂描述而非用量，不可用
- 用量提取策略：从 `herbs.usage` 通过正则提取数值范围（min_g, max_g），附于推荐药材输出

### 禁忌数据

- `herbs.contraindications`：2111/2961（71.3%）非空
- 十八反十九畏：在 `tcm_config.INCOMPATIBLE_HERBS` 中明确定义（10对十八反 + 9对十九畏 + 13味孕妇禁忌）
- `EXTENDED_TOXIC_HERBS`：6味毒性药材（生川乌/生草乌/附子/巴豆/甘遂/大戟/芫花）

## 禁忌安全筛查体系（6层）

| 层级 | 模块 | 检测内容 |
|------|------|----------|
| 1-配置定义 | `tcm_config.INCOMPATIBLE_HERBS` | 十八反10对、十九畏9对、孕妇禁用13味 |
| 2-KG图注入 | `kg/builder._add_incompatibilities()` | 将配伍禁忌注入图结构，添加 `incompatible_with` 边和毒性/妊娠标记 |
| 3-KG查询交叉 | `kg/query.herb_profile()` | 返回药材的相反相畏列表 |
| 4-症状分析 | `symptom_analysis._check_contraindications()` | 基于证型的禁忌检查（如脾胃虚弱慎用寒凉） |
| 5-模型安全 | `recommend.check_safety()` | 基于 herbs.contraindications 字段做交叉检测 |
| 6-桌面UI | `service.py` 输出 | 检测到禁忌输出 ⚠️ 提示，图谱中用红色 `#c0392b` 显示 `incompatible_with` 关系 |

## 知识图谱推理（src/kg/）

### 构建器 builder.py

实体类型（10种）：Symptom(228)、Syndrome(30)、Herb(2961)、Formula(717)、PatentMedicine(125)、FolkRemedy(216)、Category(61)、Meridian、Nature(5)、Flavor(5)
关系类型（12种）：belongs_to、recommends_herb、recommends_formula、associated_with_herb、associated_with_formula、composes、has_nature、has_flavor、has_meridian、belongs_to_category、incompatible_with、toxic、treats

### 查询接口 query.py

- `symptom_to_recommendation(symptom)` — 单症状→关联药材/方剂/证型
- `syndrome_analysis(symptom_names)` — 多症状综合分析→投票推断证型
- `herb_profile(herb_name)` — 药材完整画像（含性味归经+共现+相反相畏）
- `recommend_by_symptoms(symptoms)` — 综合推荐：多症状→多证型→综合药材+方剂（加权融合）

### KG增强推荐器 recommender.py

工作流程：模型预测 → KG推理（3条路径）→ 加权融合 → 推理路径可解释 → 安全检测
融合公式：`model_weight * 模型分 + kg_weight * KG分 + boost（若两者都推荐）`

## 知识图谱可视化 (src/desktop/kg_view.py)

基于 matplotlib + networkx 的交互式知识图谱查看器，1150 行。

### 交互特性
- **点击节点**：显示该节点的1跳邻域子图，无关节点移除节省内存，自动缩放适配视图
- **滚轮缩放**：节点圆点直径和标签字体大小随缩放比例同步变化（基于 `_base_x_range` 基准计算 zoom_factor）
- **双击**：展开邻域（1跳→2跳）
- **右键菜单**：查看详情/展开/设为中心/复制名称
- **右侧知识面板**（standalone 模式）：ScrolledText 展示节点详细属性，含药材性味归经、证型推荐、方剂组成等

### 缩放同步机制
```
首次绘制 → 记录 _base_x_range
滚轮缩放 → 计算 zoom_factor = _base_x_range / current_x_range
         → _draw_subgraph(zoom_factor) → node_size *= zoom_factor, fontsize *= zoom_factor
```
缩放范围：节点大小 20~∞，字体 5~20pt，边宽 0.5~3.0（指数衰减）。

### 布局支持
spring / circular / kamada_kawai / shell（按类型分层）四种布局可切换。

## 数据源设计原则

两套配置各有侧重，不合并：
- `tcm_config.py` — 桌面端/规则引擎用：33常见症状、9证型、15内置药材、14内置方剂。轻量，覆盖日常。无外部依赖。
- `extended_config.py` — AI/训练管线用：200症状、30证型。完整覆盖，同一包内import，无fallback。

**调用链**：
- `symptom_analysis.py` / `fallback.py` → 引用 `tcm_config.SYNDROME_DEFINITIONS`（9证型，已修复不再引用SYNDROME_RULES的3证型）
- `data_pipeline.py` → 引用 `extended_config.EXTENDED_SYNDROME_DEFINITIONS`（30证型，直接import无try-except）
- `data_pipeline._build_indices()` → 引用 `extended_config.EXTENDED_TOXIC_HERBS`（AI端副本，已解决跨包依赖）

1. **养生建议 DRY** — `tcm_config.py` 新增 `generate_health_tips()` 共享函数 + `_HEALTH_TIPS` 规则表（6组）。`fallback.py` 和 `service.py` 的养生建议逻辑统一调用该函数，消除 24 行重复代码。
2. **`detect_symptoms` 正则改进** — `fallback.py` 中关键词匹配从 `in` 操作符改为 `re.search`，同步改进 `extract_keywords()`。`query_lower` 无用变量移除。
3. **白名单"石菖蒲"重复** — `data_desensitize.py` 白名单列表中删除重复条目（`Set` 自动去重但字面不应重复）。
4. **字符集持久化** — `data_pipeline.py` 新增 `build_herb_features()` 方法，在 `save()` 时自动将药材特征（字符多热矩阵、性味归经索引）缓存到 npz 的 `herb_features` 字段。`train.py` 的 `main()` 优先从 npz 加载缓存，无需连接数据库重建特征。
5. **npz 字段完整性检查** — `train.py` 在加载 npz 后检查 `sample_weights` 和 `herb_features` 字段是否存在，缺失时打印明确提示，建议用户重新生成数据。
6. **死代码清理** — `service.py` 移除未使用的 `SymptomPipeline` 导入、`self.pipeline` 赋值和不被使用的 `_pipeline_result` 调用。

#### 待修复/待优化
1. **`knowledge_base.py` 无 FTS5 全文索引** — 5次 LIKE 全扫是性能瓶颈，建议对 efficacy/indications/functions 字段建 FTS5 虚拟表。
2. **关联矩阵精度瓶颈** — 当前症状-药材关联基于功效文本子串匹配（密度0.88%），限制了补全关联药材的质量。建议改用语义匹配（如 Sentence-BERT 或基于 embedding 的相似度）。
3. **`extended_config.py` 定义与 `tcm_config.py` 有重叠** — 两套配置共用部分症状/证型的文本定义，修改时需同步更新两者。长远可考虑用 YAML/JSON 外部配置统一管理。
4. **`_generate_herb_samples` 关联药材质量受限** — 通过 `symptom_herb_matrix` 补全的关联药材受限于文本匹配精度，部分关联可能不准确。

#### 新增改善方向（本轮发现）
5. **`data_pipeline.save()` 嵌套字典序列化兼容性** — `herb_features` 以嵌套 dict 存入 npz，通过 pickle 序列化为 0-d object array。跨 Python 大版本可能不兼容。建议未来改用独立 npz 文件或 JSON 元数据文件存储特征缓存。
6. **`build_herb_features` 重复实现** — `train.py` 和 `data_pipeline.py` 各自的 `build_herb_features` 逻辑几乎一致，违背 DRY。建议将特征构建逻辑统一放在 `data_pipeline.py` 中，`train.py` 仅从 npz 加载或调用 pipeline 方法。
7. **`fallback.py` `search_herbs`/`search_formulas` 使用 `in` 匹配** — 关键词搜索使用 `in` 操作符可能存在子串误匹配，建议统一改为 `re.search`。
8. **`result_verify.py` 导入实际均被使用** — 经代码审查，`re`（正则过滤）和 `datetime`（时间戳）均被使用，非死代码。开发文档可移除该项。
